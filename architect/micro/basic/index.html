概念 ​

  • 是将一个复杂的应用程序拆分为多个小型、独立运行的服务，每个服务聚焦于解决特定的业务领域问题（即 “单一职责”），并通过轻量级通信协议（如 HTTP/REST、gRPC）实现服务间协作，最终共同构成完整的业务系统。

示例 ​

  • 一个电商平台（如淘宝）若采用微服务架构，不会是一个 “大一统” 的程序，而是拆分为：
    • 用户服务（负责注册、登录、个人信息）、
    • 商品服务（负责商品上架、库存管理）、
    • 订单服务（负责下单、订单状态）、
    • 支付服务（负责对接支付渠道、资金流转）、
    • 物流服务（负责物流跟踪、配送管理）
  • 等多个独立服务，每个服务可单独开发、测试、部署。

特性 ​

特性描述
单一职责每个服务只专注于一个业务领域（如 “订单”“支付”），边界清晰，避免功能耦合。
独立自治服务可独立开发、测试、构建、部署，不依赖其他服务的发布周期。
轻量级通信服务间通过标准化、轻量级的协议通信，避免复杂的分布式技术栈。
数据独立存储每个服务拥有专属的数据库（或数据库实例 / 表空间），不共享数据存储。
技术栈灵活选择不同服务可根据业务需求选择最合适的技术栈（语言、框架、数据库）。
容错与弹性设计服务具备故障隔离能力，单个服务故障不扩散至整个系统。

核心架构组件 ​

服务拆分 ​

  • 基于领域驱动设计（DDD） 思想，将业务拆分为 “领域服务”，每个服务对应一个 “限界上下文”（业务边界）。

  • 按业务功能拆分： 如电商的 “用户、商品、订单、支付”。

  • 按用户角色拆分： 如 SaaS 系统的 “租户服务、管理员服务、普通用户服务”。

  • 按数据边界拆分： 如 “订单数据” 对应订单服务，“用户数据” 对应用户服务。

服务注册/发现 ​

  • 服务启动后自动注册到注册中心，其他服务通过注册中心查询服务地址（解决 “服务在哪” 问题）。
  • 服务注册工具有：Nacos、Eureka、Consul、Zookeeper、Etcd。

API 网关 ​

  • 统一入口，负责路由转发、认证授权、限流熔断、日志监控（解决 “请求怎么进” 问题）。

配置中心 ​

  • 集中管理所有服务的配置（如数据库地址、接口开关），支持动态更新（避免修改配置重启服务）。
  • 常用配置中心有：Nacos、Apollo、Spring Cloud Config。

服务通信 ​

  • 实现服务间的远程调用，分同步（如 REST、gRPC）和异步（如消息队列）两种模式。
  • 同步：Spring Cloud OpenFeign、gRPC
  • 异步：RabbitMQ、Kafka、RocketMQ

服务治理 ​

  • 保障服务稳定性，包括熔断（故障隔离）、降级（流量高峰时牺牲非核心功能）、限流（控制请求量）。
  • 熔断：Hystrix、Resilience4j
  • 降级：Sentinel、Hystrix
  • 限流：Sentinel、Resilience4j

分布式事务 ​

  • 解决跨服务操作的数据一致性问题（如 “下单” 需同时 “扣库存”，若一方失败需回滚）。
  • Seata（AT 模式）、Saga 模式、TCC 模式

监控与追踪 ​

  • 监控服务运行状态（如 CPU、接口响应时间），追踪跨服务请求链路（定位故障节点）。
  • 监控：Prometheus、Grafana
  • 追踪：Zipkin、Sleuth
