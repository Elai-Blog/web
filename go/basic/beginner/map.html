MAP ​

  • 是一种无序的键值对的集合。
  • 常用于去数据合并去重场景。

声明 ​

  • map 集合使用前一定先要 make初始化。
  • map的key 值是不重复的，具有唯一性。
go
//方式1：通过make定义
var map1 map[int]string = make(map[int]string, 10)
map1[1] = "张三"
map1[2] = "王五"

//方式2：通过make定义 不指定长度
var map2 map[int]string = make(map[int]string)
map2[1] = "张三"

//方式3: 键值对初始化
map3 := map[int]string{
    1: "张三",
    2: "王五",
}

元素操作 ​

增加 ​

go
var map1 map[int]string = make(map[int]string)
map1[1] = "one"  // 增加
map1[2] = "two"  // 增加
map1[3] = "three"
fmt.Println(map1)

输出结果

map[1:one 2:two 3:three]

修改 ​

go
map1[3] = "三"
fmt.Println(map1)

输出结果

map[1:one 2:two 3:三]

删除 ​

内置函数delete，key不存在也不会panic

go
delete(map1, 3) // 删除
fmt.Println(map1)

输出结果

map[1:one 2:two]

查询 ​

go
// 判断是否存在
v, ok := map1[4]
if ok {
    fmt.Println("存在",v)
}else{
    fmt.Println("不存在")
}

遍历 ​

map是无序的，遍历时是随机输出的。

go
// 遍历1
for i := 0; i < len(map1); i++ {
    fmt.Println(map4[i])
}
// 遍历2
for key, value := range map1 {
    fmt.Println(key, value)
}

nil map、空 map 区别 ​

go
// nil map 可以读、可以 range、可以 len，禁止赋值
var m3 map[string]string
fmt.Println(m3)
// 空 map 需要make, 可以正常读写
var m4 = make(map[string]string)
fmt.Println(m4)

输出结果

map[]

map[]

并发安全 ​

为啥不安全 ​

map 内部有状态：元素数量、扩容标记、桶迁移标记、哈希表结构。写操作会修改内部结构；如果不加同步，多个 goroutine 同时修改会破坏哈希表结构，出现内存损坏、死循环、数据错乱。

go
m := make(map[int]int)
var wg sync.WaitGroup

// 写goroutine
wg.Add(1)
go func() {
    defer wg.Done()
    for i := 0; i < 10000; i++ {
        m[i] = i
    }
}()

// 读goroutine
wg.Add(1)
go func() {
    defer wg.Done()
    for i := 0; i < 10000; i++ {
        fmt.Println(m[i])
    }
}()

wg.Wait()

输出结果

fatal error: concurrent map read and map write

解决方案 ​

map + sync.RWMutex（最常用） ​

  • 优点：简单直观，可控；读多场景 RWMutex 比 Mutex 性能好。
  • 缺点：只要写锁上来，所有读全部堵住；大量并发写时锁竞争激烈。
go
package main

import (
	"fmt"
	"sync"
)

type SafeMap struct {
	lock sync.RWMutex
	data map[string]interface{}
}

func NewSafeMap() *SafeMap {
	return &SafeMap{
		data: make(map[string]interface{}),
	}
}

// 读
func (s *SafeMap) Get(key string) (interface{}, bool) {
	s.lock.RLock()
	defer s.lock.RUnlock()
	val, ok := s.data[key]
	return val, ok
}

// 写
func (s *SafeMap) Set(key string, val int) {
	s.lock.Lock()
	defer s.lock.Unlock()
	s.data[key] = val
}

// 删除
func (s *SafeMap) Del(key string) {
	s.lock.Lock()
	defer s.lock.Unlock()
	delete(s.data, key)
}

func main() {
	sm := NewSafeMap()
	var wg sync.WaitGroup

	// 写协程
	wg.Add(1)
	go func() {
		defer wg.Done()
		sm.Set("age", 18)
	}()

	// 读协程
	wg.Add(1)
	go func() {
		defer wg.Done()
		fmt.Println(sm.Get("age"))
	}()

	wg.Wait()
}

sync.Map（专门为读多写少设计） ​

sync.Map 不是包装普通 map + 锁，是 runtime 里单独实现的结构，内部两层：read（无锁，原子访问） + dirty（带锁）

go
var sm sync.Map
var wg sync.WaitGroup

// 写
wg.Add(1)
go func() {
    defer wg.Done()
    sm.Store("name", "zhangsan")
}()

// 读
wg.Add(1)
go func() {
    defer wg.Done()
    val, ok := sm.Load("name")
    if ok {
        fmt.Println(val)
    }
}()

wg.Wait()

分片 map（分段锁，高性能方案） ​

  • 思路：把一个大 map 拆成 N 个 map，每个 map 单独一把锁。对 key 做 hash 取模，落到不同分片。
  • 好处：锁粒度变小，不同分片之间读写互不阻塞，高并发场景吞吐更高。
  • 缺点：实现复杂，需要自己维护分片、哈希、扩容。
go
type ShardedMap struct {
	shards []*shard
}
type shard struct {
	mu sync.RWMutex
	m  map[string]int
}
// 根据key hash，选shard，再操作

多台机器 ​

  • map锁是单台集群的锁，只保护当前这一台服务器进程内的并发，跨多台服务器，完全没用。
  • 多台机器采用Redis分布式锁。
  • github.com/bsm/redislock（Go 最主流，工业级，自带自动续期、阻塞、超时）
