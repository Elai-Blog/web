表 ​

  • 是数据库中用于存储和组织数据的基本结构，相当于一个二维表格，由行（记录）和列（字段）组成，是数据存储的核心单元。

表的组成 ​

  • 表名：表的唯一标识符，用于在查询中引用该表。
  • 字段（列）：表中的每个数据项都对应一个字段，字段定义了数据的类型和属性。
  • 记录（行）：表中的每一行代表一个数据记录，包含了该记录的所有字段值。
  • 索引：用于快速查找和访问表中的数据，提高查询效率。

表的操作 ​

创建表 ​

  • 表的创建语句包含了表名、字段类型、约束条件、字段描述等信息。
sql
CREATE TABLE `admin` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `name` varchar(32) COLLATE utf8mb4_general_ci NOT NULL COMMENT '账号名',
  `phone` char(11) COLLATE utf8mb4_general_ci NOT NULL COMMENT '手机号',
  `password` varchar(64) COLLATE utf8mb4_general_ci NOT NULL COMMENT '密码',
  `role_id` int NOT NULL DEFAULT '0' COMMENT '角色ID',
  `is_hid` int NOT NULL DEFAULT '0' COMMENT '是否禁用：1是 0否',
  `is_del` int NOT NULL DEFAULT '0' COMMENT '是否删除：1是 0否',
  `created_at` datetime NOT NULL,
  `updated_at` datetime DEFAULT NULL,
  `deleted_at` int NOT NULL DEFAULT '0' COMMENT '删除时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `idx_admin_phone` (`phone`)
  KEY `idx_admin_role_id` (`role_id`)
  KEY `idx_admin_is_del` (`is_del`)
) ENGINE=InnoDB AUTO_INCREMENT=1 DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
类型说明 ​
  • 参考字段类型这一章节的数据库字符集和排序规则。

约束说明 ​

约束类型描述
PRIMARY KEY主键约束，用于唯一标识表中的每一行数据，不能包含 NULL 值。
AUTO_INCREMENT自动递增约束，用于为表中的主键字段自动生成唯一的递增值。
NOT NULL非空约束，用于确保表中该列不能包含 NULL 值。
COMMENT字段注释
DEFAULT设置默认值
UNIQUE KEY唯一约束，用于确保表中该列的值是唯一的，不能重复，可以多个
Key索引约束，用于加速对表中数据的检索操作，不能重复，可以多个
ENGINE数据库引擎，用于存储和管理表的数据。默认值为 InnoDB。
CHARSET字符集约束，用于指定表中数据的字符编码。默认值为 utf8mb4。
COLLATE排序规则 默认设置：utf8mb4_general_ci

修改表 ​

  • ALTER TABLE 语句用于修改已存在的表结构，包括添加、删除、修改字段、添加索引等操作。

新增字段 ​

sql
ALTER TABLE `admin`
ADD COLUMN `birthday` DATE COMMENT "生日";

修改字段类型 ​

sql
ALTER TABLE `admin`
MODIFY COLUMN `birthday` DATETIME COMMENT "生日2";

修改字段名 ​

sql
ALTER TABLE `admin`
CHANGE COLUMN `birthday` `birth_date` DATE COMMENT "生日";

删除字段 ​

sql
ALTER TABLE `admin`
DROP COLUMN `birth_date`;

删除表 ​

sql
DROP TABLE IF EXISTS `admin`;

字符集 ​

  • 定义字符的编码规则，决定如何将字符转换为二进制存储。
字符集是否推荐描述
utf8mb4是一个字符由4个字节组成，支持所有的字符，包括 emoji。
utf8否一个字符由3个字节组成。支持基本字符，不包含 emoji。

排序规则 ​

  • 基于字符集的排序 / 比较规则
排序规则是否推荐描述
utf8mb4_general_ci是通用排序，不区分大小写（ci = case insensitive），性能较好。
utf8mb4_unicode_ci否遵循 Unicode 标准排序，更准确但性能略低（推荐用于多语言场景）。
