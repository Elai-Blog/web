索引 ​

  • MySQL 索引是数据库中用于提高查询效率的重要数据结构，它能快速定位到表中特定数据，避免全表扫描，尤其在处理大量数据时作用显著。

作用 ​

  • 提高查询效率：通过索引，数据库可以快速定位到符合条件的数据行，避免全表扫描，提高查询速度。
  • 支持排序和分组：索引可以用于对查询结果进行排序和分组操作，进一步提高查询效率。
  • 约束数据唯一性：唯一索引可以确保表中某列或多列的值唯一，避免重复数据的插入。

类型 ​

按数据结构分类 ​

B + 树索引（最常用）： ​

  • 基于 B + 树结构，叶子节点存储数据（聚簇索引）或指向数据的指针（非聚簇索引）。
  • 支持范围查询、排序，适合频繁查询和范围操作。

哈希索引： ​

  • 基于哈希表，查询速度快（O (1)），但仅支持精确匹配（=），不支持范围查询和排序。
  • MySQL 中MEMORY引擎默认使用，InnoDB 仅在自适应哈希索引（Adaptive Hash Index）中自动使用。

全文索引（FULLTEXT） ​

  • 用于文本内容的模糊查询（如MATCH AGAINST），适合长字符串。

R 树索引 ​

  • 用于空间数据类型（如GEOMETRY），支持空间范围查询。

按功能分类 ​

主键索引（PRIMARY KEY） ​

  • 唯一标识表中记录，一个表只能有一个主键，默认非空（NOT NULL）。
  • InnoDB 中，主键索引是聚簇索引，数据直接存储在叶子节点。

唯一索引（UNIQUE） ​

  • 确保索引列的值唯一（允许 NULL，但 NULL 只出现一次），可多个列组合。

普通索引（index） ​

  • 最基本的索引类型，没有任何约束，用于加速查询。

联合索引（多列索引） ​

  • 多个字段合在一起的索引，用于加速多字段查询。

最左原则 ​

  • mysql会一直从左向右匹配直到遇到索引.
  • 所以查询条件尽量把带索引的条件防止

索引失效场景 ​

索引列参与运算或使用函数 ​

sql
-- 索引列 age 参与运算，索引失效
SELECT * FROM user WHERE age + 1 = 30;

-- 索引列 name 使用函数，索引失效
SELECT * FROM user WHERE SUBSTR(name, 1, 1) = '张';

使用 NOT、!=、<> 等否定操作符 ​

sql
-- 索引列 id 使用 !=，可能失效
SELECT * FROM user WHERE id != 100;

-- NOT IN 可能导致索引失效
SELECT * FROM user WHERE age NOT IN (18, 20);

使用 OR 连接非索引列 ​

sql
-- age 有索引，name 无索引，OR 导致 age 索引失效
SELECT * FROM user WHERE age = 18 OR name = '张三';

字符串不加引号，隐式类型转换 ​

sql
-- phone 是字符串类型，查询值不加引号，索引失效
SELECT * FROM user WHERE phone = 13800138000;
-- 正确写法：phone = '13800138000'（使用索引）

模糊查询以 % 开头 ​

sql
-- name 有索引，查询以 '%张三' 开头，索引失效
SELECT * FROM user WHERE name LIKE '%张三';
-- 正确写法：name LIKE '张三%'（使用索引）

联合索引不满足最左前缀原则 ​

sql
-- 联合索引 (a, b, c)
-- 只使用 a，索引生效
SELECT * FROM t WHERE a = 1;

-- 使用 a + b，索引生效
SELECT * FROM t WHERE a = 1 AND b = 2;

-- 跳过 a 直接查 b，索引失效
SELECT * FROM t WHERE b = 2;

-- a 用范围查询（>、< 等），后续列 b、c 索引失效
SELECT * FROM t WHERE a > 1 AND b = 2;
