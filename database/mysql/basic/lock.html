锁 ​

  • 锁是用于控制并发访问数据库资源的机制，目的是保证数据的一致性和完整性。

按锁的粒度划分 ​

全局锁 ​

  • 作用范围：整个数据库实例。
  • 全库备份（如 FLUSH TABLES WITH READ LOCK）时，阻止所有写操作（增删改、建表等），保证备份数据的一致性。
  • 影响：会导致数据库只读，适合只读业务或短时间备份场景。

表级锁 ​

  • 作用范围：单个表。
  • 表共享读锁（读锁）：多个事务可同时读表，但禁止写操作（包括当前事务）。
  • 表独占写锁（写锁）：仅持有锁的事务可读写表，其他事务读写均被阻塞。
sql
# 表级别的共享锁，也就是读锁；
lock tables table_name read;

# 表级别的独占锁，也就是写锁；
lock tables table_name write;

# 解锁
unlock tables

行级锁 ​

  • 作用范围：表中的单行数据（InnoDB 引擎支持，MyISAM 不支持）。
  • 共享锁（S 锁）：事务获取后可读取该行，其他事务可加 S 锁但不可加 X 锁。
  • 独占锁（X 锁）：事务获取后可读写该行，其他事务读写均被阻塞。
sql
# 对读取的记录加共享锁(S锁)
select ... lock in share mode;
# 对读取的记录加独占锁(X锁)
select ... for update;

# 自动加锁：InnoDB 在执行 UPDATE、DELETE 时会自动为匹配行加 X 锁。

按锁的功能划分（InnoDB 特有） ​

意向锁 ​

  • 作用：表级锁，用于提前声明事务对表中 rows 的锁类型（读或写），避免表锁与行锁的冲突检查效率低下。
  • 意向共享锁（IS 锁）：事务计划对表中某些行加 S 锁。
  • 意向独占锁（IX 锁）：事务计划对表中某些行加 X 锁。
  • 规则：加行级 S 锁前需先加 IS 锁，加行级 X 锁前需先加 IX 锁；表级锁与意向锁互斥（如写锁与 IS/IX 锁互斥）。

间隙锁（Gap Lock） ​

  • 作用：锁定索引记录之间的 “间隙”（包括不存在的记录），防止其他事务插入数据，解决幻读问题（RR 隔离级别下生效）。
  • 场景：当使用范围条件（如 WHERE id > 10）加锁时，InnoDB 会锁定满足条件的行及相邻间隙。

临键锁（Next-Key Lock） ​

  • 组成：行锁 + 间隙锁的组合，是 InnoDB RR 隔离级别下默认的行级锁算法。
  • 作用：锁定索引记录本身及该记录之前的间隙，既能防止修改又能防止插入，彻底避免幻读。

插入意向锁（Insert Intention Lock） ​

  • 作用：事务插入数据时对目标间隙加的一种间隙锁，多个事务插入不同位置的记录时不会冲突。

锁的相关问题 ​

死锁 ​

  • 成因：两个或多个事务相互持有对方需要的锁，导致无限等待。
  • 解决：InnoDB 会自动检测死锁并回滚其中一个事务（代价小的那个）；也可通过合理设计索引、控制事务大小避免。

锁的等待与超时 ​

  • 当事务等待锁超过 innodb_lock_wait_timeout（默认 50 秒）时，会报超时错误。
  • 可通过 SHOW ENGINE INNODB STATUS 查看锁等待详情。

锁场景分析 ​

行锁升级为表锁（无索引导致） ​

sql
-- 表结构：id（主键），name（无索引）
-- 事务 A
BEGIN;
UPDATE user SET age = 30 WHERE name = '张三'; -- name 无索引，全表加行锁（等效表锁）

-- 事务 B（此时被阻塞）
BEGIN;
UPDATE user SET age = 40 WHERE name = '李四'; -- 即使修改不同行，仍被阻塞
  • 原因：name 无索引，事务 A 扫描全表并对所有行加 X 锁，事务 B 无法获取锁。
  • 解决：为 name 添加索引，避免全表扫描。

间隙锁导致的插入阻塞（RR 隔离级别） ​

sql
-- 表结构：id（主键，值为 10、20、30）
-- 事务 A（RR 隔离级别）
BEGIN;
SELECT * FROM user WHERE id BETWEEN 10 AND 20 FOR UPDATE;
-- 锁定 id=10、20 的行，以及间隙 (20,30)，防止插入 21-29 的数据

-- 事务 B（被阻塞）
BEGIN;
INSERT INTO user (id) VALUES (25); -- 插入间隙 (20,30) 中的值，被间隙锁阻塞
  • 原因：RR 级别下范围查询会加临键锁（行锁 + 间隙锁），阻止插入间隙内的数据，解决幻读。
  • 解决：等前面事务执行完毕，或者隔离级别改为 RC 级别（禁用间隙锁）。

死锁案例 ​

sql
-- 表结构：id（主键），a、b（均为索引）
-- 事务 A
BEGIN;
UPDATE user SET a = 1 WHERE id = 1; -- 锁定 id=1 的行（X 锁）
UPDATE user SET b = 1 WHERE id = 2; -- 等待事务 B 释放 id=2 的锁

-- 事务 B
BEGIN;
UPDATE user SET b = 2 WHERE id = 2; -- 锁定 id=2 的行（X 锁）
UPDATE user SET a = 2 WHERE id = 1; -- 等待事务 A 释放 id=1 的锁
  • 原因：两事务相互等待对方的锁，InnoDB 检测到死锁后，回滚其中一个事务（通常是修改行数少的）。
  • 解决：
    • 统一事务内的更新顺序（如都按 id 从小到大更新）。
    • 减少事务持有锁的时间（拆分长事务）。
