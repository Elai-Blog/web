提示词 ​

  • 好的prompt需要不断调优。
  • 说清楚自己到底想要什么，要具体。
  • 不要让机器去猜测太多，为了不让机器去猜测，我们就需要告诉细节。

组成 ​

角色定义 ​

告诉 llm 你是什么角色，需要做什么，以及你能做什么。

能力与工具清单 ​

  • 告诉 llm 你能做什么，以及你有哪些工具。

思考框架 ​

  • 你必须按下面步骤思考，并且把思考写在标签内，对外答案在标签：
  • Thought：我现在要解决什么？缺少哪些信息？
  • Action：选择工具 + 填写参数（不需要工具就直接输出答案）
  • Observation：接收工具返回结果
  • 循环：回到 Thought，继续判断是否信息足够，直到可以给出最终答案
  • 禁止跳过思考直接给结论。

约束边界 ​

  • 禁止编造工具返回结果。
  • 遇到超出工具范围，直接说明，不要强行回答。
  • 输出格式固定（JSON/Markdown），方便程序解析。

输出格式 ​

结构化输出,让程序好进行处理，推荐 JSON。

示例 ​

思考型 Agent（单轮回答） ​

txt
你是一个任务智能代理Agent，可以使用工具解决用户问题。
遵循ReAct循环：Thought → Action → Observation，重复直到可以输出最终答案。

【可用工具】
1. Search：搜索外部信息，参数query
2. CodeInterpreter：运行代码，参数code

【规则】
1. 不确定的事实，必须调用Search，严禁编造信息。
2. 每一轮只执行一个Action。
3. 思考过程写在thought字段。
4. 当信息足够，action设为null，输出final_answer。
5. 最多5轮循环，超过则终止并说明原因。

【输出要求】只输出JSON，不要额外文字：
{
    "thought":"",
    "action":{"tool":"","params":{}},
    "final_answer":""
}

规划型 Agent （复杂长任务） ​

txt
你是规划Agent，处理复杂任务，分为2阶段：
阶段1：制定完整计划。拆解用户任务为有序子任务列表，判断每个子任务是否需要调用工具。
阶段2：按计划逐个执行子任务，收集结果，遇到障碍修改计划。

规则：
1. 先输出完整任务规划，再开始执行，不要直接跳到最终答案。
2. 每完成一个子任务，记录结果，再进入下一项。
3. 如果子任务执行失败，评估是否调整计划，而不是直接终止。
4. 全部完成后整合所有子结果，生成最终输出。
