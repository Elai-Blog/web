页面导航

pod ​

  • Pod 是 Kubernetes 最小调度单元

生成周期 ​

  • Pending：创建中，镜像拉取 / 调度节点
  • Running：容器正常运行
  • Completed：一次性任务执行完毕（Job/CronJob）
  • Error：容器启动失败、崩溃
  • CrashLoopBackOff：容器反复重启
  • Unknown：节点失联，无法获取 Pod 状态

管理pod ​

pod 列表 ​

bash
# 查看pod
kubectl get pods
# 指定命名空间
kubectl get pod -n default
# 显示更多信息（IP、节点）
kubectl get pods -o wide
# 实时监控状态
kubectl get pods -w

pod 详情 ​

bash
# 查看pod详情
kubectl describe pod <pod-name>

pod 日志 ​

bash
# 查看pod日志
kubectl logs <pod-name>

pod 删除 ​

bash
# 删除pod
kubectl delete pod <pod-name>

pod 启动 ​

bash
# 方式1：使用 YAML 文件启动 Pod
kubectl create -f <pod-yaml>
# 方式2：使用命令行参数启动 Pod
kubectl run <pod-name> --image=<image-name> --port=<port>
yaml
# yaml 配置nginx
apiVersion: v1
# 配置
kind: Pod
metadata:
    name: pod-nginx
    namespace: default
    labels:
        # 设置标签
        app: pod-nginx
spec:
    # 配置镜像
    containers:
        # - 表示数组 可以配置多个
        # name 是容器名称
        - name: nginx-container
          # 拉取的镜像地址
          image: nginx:alpine
          # 镜像拉取策略：• Always：每次创建都拉取• IfNotPresent：本地没有才拉取（默认）• Never：只使用本地镜像
          imagePullPolicy: IfNotPresent
          # 配置端口
          ports:
              - containerPort: 80
          resources: # 资源限制（防资源抢占，生产必须配置）
              requests: # 最小分配资源
                  cpu: '100m' # 100毫核，1核=1000m
                  memory: '128Mi'
              limits: # 最大占用资源，超量会被限流/杀死
                  cpu: '200m'
                  memory: '256Mi'

pod 进入 ​

bash
# 进入pod
kubectl exec -it <pod-name> -- /bin/bash

多容器pod ​

  • 一个pod同时运行多个容器
  • 示例：一个 Pod 运行 Nginx + 日志采集容器 busybox，共享网络与存储
bash
apiVersion: v1
kind: Pod
metadata:
  name: sidecar-pod
spec:
  volumes: # 共享存储卷
  - name: log-volume
    emptyDir: {} # 临时空目录，Pod删除数据丢失
  containers:
    # 主容器nginx
    - name: nginx
        image: nginx
        volumeMounts:
        - name: log-volume
        mountPath: /var/log/nginx # nginx日志挂载到共享卷
    # sidecar日志采集容器
    - name: log-sidecar
        image: busybox
        command: ["tail","-f","/log/access.log"] # 实时打印日志
        volumeMounts:
        - name: log-volume
        mountPath: /log

重启规则 ​

  • restartPolicy：容器重启策略，默认 Always
    • Always：容器崩溃后自动重启
    • OnFailure：容器崩溃后仅重启失败容器
    • Never：容器崩溃后不重启

故障排查 ​

Pod 状态 Pending（起不来） ​

bash
kubectl describe pod xxx
# 重点看 Events 事件：
# 1. 镜像名称写错/镜像仓库无法拉取 ImagePullBackOff
# 2. 节点资源不足（CPU内存不够调度失败）
# 3. 权限、镜像私有仓库密钥缺失

CrashLoopBackOff 反复重启 ​

bash
1. 查看日志：`kubectl logs pod-name`
2. 查看上一次崩溃日志：`kubectl logs -p pod-name`
3. 检查资源 limits 是否过小，OOM 杀死（describe 里会提示 OOMKilled）
4. 检查容器启动命令是否报错、端口冲突

Pod Running 但无法访问 ​

bash
1. 进入容器 `curl localhost:端口` 验证内部服务是否正常
2. 检查安全组 / 网络策略 NetworkPolicy
3. 端口映射是否正确 containerPort
4. 跨 Pod 访问确认 Pod IP 连通性

容器无法写入文件 ​

bash
检查：挂载卷读写权限、securityContext 权限配置

重要生产注意事项 ​

  1. 禁止直接裸 Pod 运行业务 Pod 删除重建 IP 变化、无自愈、无扩缩容，生产必须用 Deployment/StatefulSet 管理 Pod，裸 Pod 仅临时调试。
  2. 必须配置 resources.requests/limits，防止节点资源耗尽
  3. 多用标签 labels 管理 Pod，方便筛选、灰度、监控
  4. 不要硬编码 Pod IP，服务发现使用 Service + ClusterIP
  5. 多容器仅用于辅助 Sidecar，主业务单独拆分 Pod 更易维护
