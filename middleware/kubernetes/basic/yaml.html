apiVersion: apps/v1 # API版本，不同资源版本不同

kind ​

  • 资源类型配置
  • 日常开发 90% 场景只用：Deployment、Service、Ingress、ConfigMap、Secret、PVC、StatefulSet、Job、CronJob

核心资源（最常用） ​

Kind中文名称核心作用使用场景简述
Pod容器组K8s 最小调度单元，运行一个或多个容器直接跑业务容器；一般不手动创建，由控制器管理
Deployment部署控制器无状态应用编排、滚动更新、扩缩容、自愈Web 服务、后端 API、无状态程序（绝大多数业务首选）
StatefulSet有状态集有状态应用，稳定网络标识、持久存储有序创建MySQL、Redis 集群、ZooKeeper、MongoDB 等有状态中间件
DaemonSet节点守护集每个节点运行一个 Pod 实例日志采集（Filebeat）、监控 Agent、节点网络插件、杀毒程序
ReplicaSet副本集保证指定数量 Pod 副本运行Deployment 底层依赖，几乎不单独写 YAML 创建
Job一次性任务执行一次性任务，完成即退出数据备份、批量脚本、一次性数据迁移
CronJob定时任务周期性定时执行 Job定时备份、定时统计、定时清理数据（类似 Linux crontab）

服务 & 网络资源 ​

Kind中文名称核心作用使用场景简述
Service服务为一组 Pod 提供固定访问入口、负载均衡内部 Pod 互相访问、暴露应用访问地址，四种模式 ClusterIP/NodePort/LoadBalancer/ExternalName
Ingress入口网关HTTP/HTTPS 七层路由、域名反向代理多域名、路径路由、SSL 证书配置，对外暴露 Web 服务
IngressClassIngress 类区分不同 Ingress 控制器实现集群部署多个 ingress-nginx 等控制器时做绑定选择
NetworkPolicy网络策略Pod 之间网络访问权限控制（防火墙）微服务隔离、限制 Pod 入 / 出站流量安全管控

配置 & 敏感信息资源 ​

Kind中文名称核心作用使用场景简述
ConfigMap配置字典存放非敏感配置、环境变量、配置文件应用配置文件、启动参数、普通环境变量注入
Secret密钥存放加密敏感数据（密码、密钥、Token）数据库账号、SSL 私钥、API 密钥、凭证信息

存储资源 ​

Kind中文名称核心作用使用场景简述
PersistentVolume(PV)持久卷集群外部存储资源（NFS、云盘、SAN 等）预先创建存储供给使用
PersistentVolumeClaim(PVC)持久卷申请Pod 申请存储空间，自动绑定 PV业务挂载持久化存储，解耦应用与存储细节
StorageClass存储类动态供给 PV，自动创建存储无需手动建 PV，创建 PVC 自动分配存储（云环境主流）

权限 & 账号资源（RBAC） ​

Kind中文名称核心作用使用场景简述
ServiceAccount(SA)服务账号Pod 在集群内部访问 API 的身份账号程序调用 k8s API、内部授权访问
Role角色命名空间内细粒度权限集合某个命名空间内增删改查指定资源权限
ClusterRole集群角色全局集群级权限，跨所有命名空间集群管理员、节点管理、全局资源权限
RoleBinding角色绑定把 Role 绑定到用户 / SA / 组命名空间内分配权限
ClusterRoleBinding集群角色绑定把 ClusterRole 全局绑定主体全局赋予集群级权限

节点 & 集群管理资源 ​

Kind中文名称核心作用使用场景简述
Node节点集群宿主机节点对象查看节点状态、污点、标签，一般不由用户创建
Namespace(NS)命名空间资源逻辑隔离，分组管理资源环境隔离：dev/test/prod，区分不同项目资源
Event事件集群各类操作日志事件排查 Pod 启动失败、调度异常、报错原因
LimitRange资源限制范围限制单个 Pod / 容器默认 CPU 内存上下限防止单个容器资源超限占用节点
ResourceQuota资源配额命名空间总资源上限（CPU、内存、Pod 总数）多租户集群，限制命名空间整体资源开销

metadata ​

  • 描述这个资源
字段含义是否必填作用说明
name资源名称必选当前资源唯一名字，同命名空间内不能重名；小写字母、数字、-、.，不能以 -/. 开头结尾
namespace命名空间可选（默认 default）指定资源所属命名空间，做环境隔离
labels标签可选键值对，用于筛选、匹配、选择器匹配（Service、Deployment 匹配 Pod 靠标签）
annotations注解可选键值对，存放额外描述信息，不用于选择器匹配，给控制器 / 插件读取配置
uid唯一 ID系统自动生成全局唯一标识，用户一般不手动填写
resourceVersion资源版本系统自动生成用于并发控制、判断资源是否变更，watch 依赖此字段
generation代数版本系统自动生成记录配置更新次数，区分配置版本和运行状态版本
creationTimestamp创建时间系统自动生成资源创建时间，不可手动修改
deletionTimestamp删除时间戳系统自动生成发起删除后填充，代表优雅删除截止时间
deletionGracePeriodSeconds删除宽限期可选容器停止等待秒数，默认 30s，自定义优雅退出时长
ownerReferences属主引用系统自动生成标识资源所属父控制器（如 Pod 归属 Deployment），级联删除依赖此字段
finalizers终结器可选删除资源前执行清理逻辑，清理完成才真正删除资源

spec ​

  • 资源期望配置 / 期望状态，定义你想要这个资源长什么样、怎么运行、规则是什么

Pod.spec（最小单元，最基础） ​

字段作用说明
containers必填，容器列表，定义运行的镜像、命令、端口、资源、挂载、环境变量
initContainers初始化容器，先执行完才启动业务容器（初始化配置、拉取文件、等待数据库就绪）
volumes定义存储卷，供容器挂载使用
restartPolicy重启策略：Always(默认) / OnFailure / Never
nodeSelector节点标签匹配，调度到指定标签节点
nodeName强制调度到某个具体节点名
tolerations容忍节点污点，能调度到带污点节点
affinity亲和性（节点亲和、Pod 亲和、Pod 反亲和）精细化调度
serviceAccountNamePod 使用的服务账号
imagePullSecrets私有镜像仓库拉取镜像密钥
hostNetwork是否使用宿主机网络（true 占用宿主机端口）
dnsPolicy / dnsConfigDNS 策略、自定义 DNS 配置

Deployment.spec（最常用无状态部署） ​

字段作用
replicas期望 Pod 副本数量
selector.matchLabels必填，匹配 Pod 标签，控制器管理哪些 Pod
templatePod 模板，内部 template.metadata + template.spec，新建 Pod 以此模板创建
strategy更新策略：滚动更新 RollingUpdate / 重建更新 Recreate
minReadySecondsPod 就绪后等待多久才算可用
revisionHistoryLimit保留历史版本个数，用于回滚
progressDeadlineSeconds部署超时时间

StatefulSet.spec（有状态应用） ​

字段说明
replicas副本数
selector.matchLabelsPod 标签选择器
templatePod 模板
serviceName必须配置，绑定一个 Headless Service，用于稳定网络域名
volumeClaimTemplatesPVC 模板，每个 Pod 自动创建独立持久化存储
updateStrategy更新策略

DaemonSet.spec（每个节点跑一个 Pod） ​

字段作用
replicas期望 Pod 副本数量
selector.matchLabels必填，匹配 Pod 标签，控制器管理哪些 Pod
templatePod 模板，内部 template.metadata + template.spec，新建 Pod 以此模板创建
strategy更新策略：滚动更新 RollingUpdate / 重建更新 Recreate
minReadySecondsPod 就绪后等待多久才算可用
revisionHistoryLimit保留历史版本个数，用于回滚
progressDeadlineSeconds部署超时时间

Job / CronJob.spec ​

  • 一次性任务
yaml
spec:
    template: # Pod模板
    completions: 1 # 需要成功完成多少个
    parallelism: 1 # 并行运行个数
    backoffLimit: 3 # 失败重试次数
    activeDeadlineSeconds: 3600 # 任务最长运行超时时间
  • 定期任务
yaml
spec:
    schedule: '*/5 * * * *' # cron表达式
    jobTemplate: # 嵌套Job模板
        spec:
            template: {}
    concurrencyPolicy: Forbid # 并发策略 Forbid/Replace/Allow
    startingDeadlineSeconds: 100

Service.spec（服务访问、负载均衡） ​

字段作用

Ingress.spec（七层域名路由） ​

yaml
spec:

参数说明 ​

pod.containers ​

参数名类型是否常用详细说明
namestring必填容器名称，同一 Pod 内不能重复；小写字母、数字、横杠
imagestring必填容器镜像地址，如 nginx:1.25-alpine、私有仓库镜像地址
imagePullPolicystring常用镜像拉取策略：• Always：每次创建都拉取• IfNotPresent：本地没有才拉取（默认）• Never：只使用本地镜像
command[]string按需用覆盖容器镜像默认 ENTRYPOINT；数组形式 ["/bin/sh","-c"]
args[]string按需用覆盖镜像默认 CMD，作为 command 后续参数
ports[]Port常用容器端口列表，定义容器监听端口，用于端口暴露、探针识别
env[]EnvVar常用直接定义环境变量（键值对）
envFrom[]EnvFromSource常用从 ConfigMap / Secret 批量导入环境变量
resourcesResourceRequirements常用CPU、内存资源配额：requests（申请保底资源）、limits（最大限制）
volumeMounts[]VolumeMount常用将 Pod 顶层 volumes 挂载到容器内部路径
workingDirstring按需用容器启动工作目录，覆盖镜像默认 WORKDIR
stdinbool调试用是否开启标准输入，交互式调试容器用
stdinOncebool调试用stdin 只打开一次
ttybool调试用分配终端（等价 kubectl run -it）
livenessProbeProbe生产必备存活探针：检测容器是否卡死，异常则重启容器
readinessProbeProbe生产必备就绪探针：检测容器是否能接收流量，就绪后加入 Service 端点
startupProbeProbe慢启动应用必备启动探针：针对启动慢的程序，前期屏蔽存活探针判断
securityContextSecurityContext生产常用容器权限配置：运行用户、UID/GID、是否特权、capabilities、只读根文件系统等
lifecycleLifecycle按需使用容器生命周期钩子：postStart 容器启动后执行preStop 容器停止前优雅执行
terminationMessagePathstring极少用容器异常退出信息写入路径，默认 /dev/termination-log
terminationMessagePolicystring极少用退出信息收集策略：File / FallbackToLogsOnError

使用案例 ​

配置nginx ​

yaml
apiVersion: apps/v1
# 配置
kind: Deployment
metadata:
    name: base-nginx
    namespace: base
    labels:
        # 设置标签
        app: base-1-nginx
spec:
    replicas: 2
    selector:
        # 关联标签 template.metadata.labels
        matchLabels:
            app: base-2-nginx
    # 设置pod模板 内部 template.metadata + template.spec，
    template:
        metadata:
            labels:
                app: base-2-nginx
        spec:
            # 配置镜像
            containers:
                # - 表示数组 可以配置多个
                # name 是容器名称
                - name: base-3-nginx
                  # 拉取的镜像地址
                  image: nginx:1.27
                  # 镜像拉取策略：• Always：每次创建都拉取• IfNotPresent：本地没有才拉取（默认）• Never：只使用本地镜像
                  imagePullPolicy: IfNotPresent
                  # 配置端口
                  ports:
                      - containerPort: 80
                  # 资源限制
                  resources:
                      # 保底资源
                      requests:
                          # 使用多少核cpu 下面定义0.2核=200m
                          cpu: 200m
                          # 使用多少内存
                          memory: 128Mi
                      # 资源上限
                      limits:
                          # 使用多少核cpu 下面定义1核=1000m
                          cpu: 1000m
                          # 使用多少内存
                          memory: 1Gi
                  # 就绪探针 HTTP 方式：判断 80 端口是否能正常访问
                  readinessProbe:
                      httpGet:
                          path: /
                          port: 80
                          scheme: HTTP
                      # 容器启动后等待多久第一次探测
                      initialDelaySeconds: 3
                      # 探测间隔
                      periodSeconds: 10
                      # 单次探测超时时间
                      timeoutSeconds: 3
                      # 连续失败几次判定异常
                      failureThreshold: 3
                      # 连续成功几次判定就绪
                      successThreshold: 1
                  # 存活探针 HTTP 方式
                  livenessProbe:
                      httpGet:
                          path: /
                          port: 80
                          scheme: HTTP
                      # 容器启动后等待多久第一次探测
                      initialDelaySeconds: 3
                      # 探测间隔
                      periodSeconds: 10
                      # 单次探测超时时间
                      timeoutSeconds: 3
                      # 连续失败几次判定异常
                      failureThreshold: 3
