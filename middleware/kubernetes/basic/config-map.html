页面导航

config-map ​

  • ConfigMap（简称 CM）是 Kubernetes 用于存放非敏感配置数据的资源对象，专门分离容器镜像和配置.

存储什么 ​

  • 环境变量、配置文件、命令行参数、应用配置（nginx.conf、application.yml、properties 等）

创建方式 ​

键值对 ​

yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: app-cm
    namespace: default
    labels:
        app: app-cm
data:
    ENV: 'prod'
    SERVER_PORT: '8080'
    LOG_LEVEL: 'warn'

配置文件 (用的多) ​

  • nginx.conf配置
yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: nginx-cm
    namespace: default
    labels:
        app: nginx-cm
data:
    # key为文件名，value为完整配置内容
    nginx.conf: |
        server {
            listen 80;
            server_name localhost;
            location / {
                root /usr/share/nginx/html;
                index index.html;
            }
        }
  • go配置
yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: go-cm
    namespace: default
    labels:
        app: go-cm
data:
    backend-api.yaml: |
        Name: backend-api
        Host: 0.0.0.0
        Port: 8100

        Log:
            ServiceName: backend-api #服务名称
            Mode: console # 日志模式,console-输出到console,file-输出到当前服务器(容器)文件,volume-输出docker挂在文件内
            Encoding: plain # 日志展示方式，开发选择plain，生产json default=json,options=[json,plain]
            TimeFormat: 2006-01-02 15:04:05 #时间格式
            Path: logs # 日志存储路径，默认logs
            Level: info # 日志写入级别 info|error|severe
            Compress: true # 是否开启gzip压缩
            KeepDays: 15 # 日志保留天数
            StackCooldownMillis: 100 # 日志write间隔，默认100  #多少毫秒后再次写入堆栈跟踪。用来避免堆栈跟踪日志过多
            MaxBackups: 0 # default=0
            MaxSize: 0 # default=0
            Rotation: daily # `json:",default=daily,options=[daily,size]"`
            Stat: true # 是否开启stat服务，1.4.4版本新增参数`json:",default=true"`

使用方式 ​

环境变量注入 env ​

  • 程序代码需要自己读环境env
yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: app-cm
    namespace: default
    labels:
        app: app-cm
data:
    env: 'prod'
    port: '8080'
    log.level: 'warn'
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    containers:
        - name: app
          image: busybox
          command: ['sleep', '3600']
          env:
              # 单个变量取自ConfigMap
              - name: APP_ENV
                valueFrom:
                    configMapKeyRef:
                        name: app-cm # cm名称
                        key: env # cm内的key
              - name: APP_PORT
                valueFrom:
                    configMapKeyRef:
                        name: app-cm
                        key: port
              - name: APP_LOG_LEVEL
                valueFrom:
                    configMapKeyRef:
                        name: app-cm
                        key: log.level

一次性导入为环境变量（envFrom） ​

  • 简洁写法，自动把 CM 全部 key 转为环境变量
  • 程序代码需要自己读env
yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: app-cm
    namespace: default
    labels:
        app: app-cm
data:
    env: 'prod'
    port: '8080'
    log.level: 'warn'
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    containers:
        - name: app
          image: busybox
          command: ['sleep', '3600']
          envFrom:
              - configMapRef:
                    name: app-cm

挂载为容器内文件（volumeMounts，最常用） ​

  • 把 CM 里的每条 key 映射成一个文件，value 为文件内容，支持热更新：
yaml
apiVersion: v1
kind: ConfigMap
metadata:
    name: app-cm
    namespace: default
    labels:
        app: app-cm
data:
    # key 必须是conf文件名，value是nginx真实配置
    default.conf: |
        server {
            listen 80;
            server\_name _;
            location / {
                root   /usr/share/nginx/html;
                index  index.html;
            }
        }
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    volumes:
        # 挂载卷名称
        - name: config-volume
          # 关联 configMap
          configMap:
              name: app-cm # cm名称
    containers:
        - name: nginx
          image: nginx
          ports:
              - containerPort: 80
          # 挂载到容器目录
          volumeMounts:
              - name: config-volume # 挂载名称
                # 把CM里所有文件挂载到 /etc/nginx/conf.d 目录
                mountPath: /etc/nginx/conf.d # 挂载目录
                readOnly: true # 只读

更新机制 ​

  • 文件挂载方式: 修改 CM → k8s 异步更新挂载的文件（通常 10s 内），应用如果读取文件是实时加载则立刻生效；若应用启动时一次性加载到内存，依然需要重启 Pod。
  • 环境变量注入方式 : 环境变量在容器初始化时拷贝一份存入内存，CM 修改永远不会自动更新，必须滚动重启

避坑 ​

  • 配置文件优先使用文件挂载方式，便于动态更新配置
  • 数据库地址、账号明文禁止放入 ConfigMap，必须使用 Secret
  • 超大配置文件（>1MiB）不要使用 CM，改用 PV 挂载配置文件
  • 生产环境 CM 全部用 YAML 文件管理，纳入 git 版本控制，不要用 kubectl create 命令临时创建
  • subPath 挂载的文件不会自动更新，subPath 机制会屏蔽热更新，需要更新必须重启 Pod
  • 多环境区分：不同命名空间创建同名 CM，实现环境配置隔离
