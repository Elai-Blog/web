Service ​

  • 将外部流量分发到后端 Pod，实现负载均衡。

工作原理 ​

  • Service 通过 spec.selector 匹配 Pod 的 labels，把符合条件的 Pod 纳入后端端点列表（Endpoints）。

类型 ​

类型说明使用场景
ClusterIP默认，仅集群内部访问后端服务之间互相调用（数据库、缓存、内部微服务）
NodePort通过节点 IP + 端口暴露服务
LoadBalancer云厂商负载均衡仅公有云环境（阿里云、腾讯云、AWS）可用
ExternalName映射集群外部服务把 Service 映射到集群外部的地址（例如 RDS、外网域名）

ClusterIP ​

  • K8s 自动分配一个集群内网虚拟 IP（ClusterIP），该 IP 仅在集群内部（Pod、节点）可访问，外网无法直接访问，是默认的 Service 类型。
  • 编写service_cluster_ip.yaml
yaml
apiVersion: v1
kind: Service
metadata:
    # 服务名称
    name: cluster-ip-nginx-svc
    namespace: base
spec:
    type: ClusterIP
    selector:
        # 绑定的项目
        app: nginx-pod
    ports:
        - protocol: TCP
          port: 80
          targetPort: 80
  • 运行kubectl apply -f service_cluster_ip.yaml
  • 检查运行结果kubectl get svc -n base
  • 查看详情kubectl describe svc base-nginx-svc -n base
bash

NodePort ​

  • 在 集群所有节点 开启一个固定端口（范围30000-32767），外部用户通过 节点IP:NodePort端口 即可访问服务。NodePort 底层依赖 ClusterIP，自动兼容集群内部访问。
yaml
apiVersion: v1
kind: Service
metadata:
    name: node-port-nginx-svc
    namespace: default
spec:
    type: NodePort
    selector:
        app: nginx-pod
    ports:
        - protocol: TCP
          port: 80
          targetPort: 80

LoadBalancer ​

  • LoadBalancer 是云厂商（阿里云、腾讯云、AWS）专属类型，基于 NodePort 实现，云厂商控制器会自动创建 公网负载均衡器，分配独立公网 IP，将公网请求转发到集群节点，再转发至后端 Pod。
bash
apiVersion: v1
kind: Service
metadata:
  name: load-balancer-nginx-svc
  namespace: default
spec:
  type: LoadBalancer
  selector:
    app: nginx-pod
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  # 云厂商可配置负载均衡参数（可选）
  externalTrafficPolicy: Cluster  # 保留源IP，Local则不转发跨节点请求

ExternalName ​

  • 唯一无端口、无代理、无负载均衡的 Service 类型，仅做 DNS CNAME 转发，将集群内的 Service 域名映射到外部域名，实现集群内统一访问外部第三方服务。
bash
apiVersion: v1
kind: Service
metadata:
  name: external-name-nginx-svc
  namespace: default
spec:
  type: ExternalName
  externalName: mysql.xxx.com  # 外部真实域名

kube-proxy ​

  • kube-proxy 是节点上负责实现 Service 转发的核心组件

iptables（默认旧模式） ​

  • 纯内核 iptables 规则，无代理进程；
  • 流量随机转发，不支持会话保持；
  • 大规模集群（上千 Pod）iptables 规则爆炸，性能差。

ipvs（生产推荐） ​

  • 基于 Linux IPVS 模块，专门四层负载均衡；
  • 规则存储哈希表，万级 Pod 性能无衰减；
  • 支持多种调度算法：rr (轮询)、wrr (加权轮询)、lc (最小连接)、sh (源 IP 哈希会话保持)； 开启方式：kube-proxy 配置 mode: ipvs

userspace（废弃，不使用） ​

  • kube-proxy 用户态进程转发，性能极差，早期版本遗留。

无头服务 ​

  • spec.clusterIP: None 即为无头服务
  • 不分配 ClusterIP，不会做负载均衡
  • DNS 直接解析为后端所有 Pod IP，常用于有状态应用（MySQL、Redis、StatefulSet）
yaml
apiVersion: v1
kind: Service
metadata:
    name: mysql-headless-svc
    namespace: default
spec:
    clusterIP: None # 关键：无头服务标识
    selector:
        app: mysql-sts
    ports:
        - port: 3306
          targetPort: 3306

流量调度 ​

外部流量策略 ​

  • Cluster（默认）：流量可转发到集群任意节点的 Pod，源 IP 会被 SNAT 修改，后端 Pod 看不到真实客户端 IP；
  • Local：流量仅转发到当前节点的 Pod，源 IP 会保持不变，后端 Pod 可以获取到真实客户端 IP；
yaml
spec:
    type: NodePort
    externalTrafficPolicy: Local

端口多协议 & 多端口 ​

yaml
ports:
    - port: 80
      targetPort: http
      name: http
    - port: 443
      targetPort: https
      name: https
      protocol: TCP
