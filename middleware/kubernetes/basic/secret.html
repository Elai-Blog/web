secret ​

  • 是 Kubernetes 内置资源对象，用于安全存储敏感数据：密码、密钥、数据库账号、TLS 证书、AccessToken、私钥等。

类型 ​

类型取值用途
通用 Opaque（默认）Opaque自定义任意键值（账号密码、token 等，最常用）
服务账号令牌kubernetes.io/service-account-token自动创建，Pod 访问 K8s APIServer 的认证令牌
Docker 镜像密钥kubernetes.io/dockerconfigjson拉取私有镜像仓库的登录凭证
TLS 证书kubernetes.io/tls存放 HTTPS 证书 (crt) 和私钥 (key)

创建 ​

数据库秘钥 ​

yaml
apiVersion: v1
kind: Secret
metadata:
    name: db-secret
    namespace: default
type: Opaque
# data: 需要手动base64编码填写
data:
    username: cm9vdA== # root base64
    password: MTIzNDU2 # 123456 base64
# stringData: 明文书写，k8s创建时自动转base64，优先级高于data同名key
stringData:
    DB_USER: root
    DB_PASS: My@Pass123
    DB_HOST: mysql-service
    DB_PORT: '3306'

使用 ​

挂载为文件（Volume 挂载） ​

  • Secret 内每个 key 会变成一个文件，value 为文件内容
yaml
apiVersion: v1
kind: Secret
metadata:
    name: db-secret
    namespace: default
type: Opaque
stringData:
    DB_USER: root
    DB_PASS: My@Pass123
    DB_HOST: mysql-service
    DB_PORT: '3306'
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    # 定义挂载卷
    volumes:
        - name: db-volume # 卷名 挂载使用
          # 使用secret
          secret:
              secretName: db-secret # 挂载的 secret 名称，参考上面
    # 申请容器
    containers:
        - name: app
          image: nginx
          # 使用
          volumeMounts:
              - name: db-volume
                mountPath: /etc/db-secret # 容器内路径
                readOnly: true # secret 必须只读

注入环境变量（最常用） ​

  • 单个注入
yaml
apiVersion: v1
kind: Secret
metadata:
    name: db-secret
    namespace: default
type: Opaque
data:
    username: cm9vdA== # root base64
    password: MTIzNDU2 # 123456 base64
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    container:
        - name: app
          image: nginx
          env:
            - name: DB_USER
                valueFrom:
                    secretKeyRef:
                        name: db-secret
                        key: username
                - name: DB_PWD
                valueFrom:
                    secretKeyRef:
                        name: db-secret
                        key: password
  • 批量注入
yaml
apiVersion: v1
kind: Secret
metadata:
    name: db-secret
    namespace: default
type: Opaque
data:
    username: cm9vdA== # root base64
    password: MTIzNDU2 # 123456 base64
---
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    container:
      - name: app
          image: nginx
          envFrom:
            - secretRef:
                name: db-secret

    name: base-backend
    namespace: base

    imagePullSecrets:
        - name: harbor-secret
    containers:
        - name: myapp
          image: harbor.example.com/myapp:v1

更新机制 ​

  1. 环境变量方式注入 Secret：Pod 启动时一次性读取，Secret 更新后 Pod 不会自动生效，必须重建 Pod
  2. Volume 文件挂载方式：kubelet 会周期性同步（默认一分钟），容器内文件会自动刷新，无需重启 Pod

生产实践 ​

短板 ​

  • 原生 Secret 仅 Base64 编码，etcd 裸数据可读，集群管理员可直接解码获取明文
  • Secret 存放在 etcd，备份 etcd 文件等于泄露所有密钥
  • 所有同命名空间下 Pod 默认可访问 secret（需 RBAC 隔离）

生产建议 ​

  • 开启 etcd 数据加密（K8s 原生加密配置）
  • 不要在 Git 提交原生 Secret yaml（base64 依然是明文）
  • 最小权限：用 RBAC 限制 ServiceAccount 读取 Secret
  • 避免大量数据放入 Secret（推荐单个 Secret 小于 1MB）
