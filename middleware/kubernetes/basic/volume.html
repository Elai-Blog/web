容器卷 ​

  • 容器生命周期数据丢失：容器删除 / 重建后，容器内部文件系统数据全部清空（容器本地存储是临时的）。
  • 多容器共享文件：同一个 Pod 内多个容器无法直接共享读写文件目录。
  • 宿主机文件挂载：需要把宿主机配置、日志、证书挂载进容器。
  • 数据持久化：数据库、Redis 这类有状态服务必须落地持久存储。

类型 ​

yaml
volumes:
    - name: '卷名称' # 必填，唯一标识，volumeMounts 通过 name 匹配
      # 下面【任选一个】存储类型字段，一个volume只能有一种存储后端
      emptyDir: {}
      hostPath: {}
      persistentVolumeClaim: {}
      configMap: {}
      secret: {}
      downwardAPI: {}
      projected: {}
      persistentVolume: {}
      awsElasticBlockStore: {}
      azureDisk: {}
      azureFile: {}
      gcePersistentDisk: {}
      glusterfs: {}
      nfs: {}
      iscsi: {}
      cephfs: {}
      rbd: {}
      flexVolume: {}
      csi: {}
      photonPersistentDisk: {}
      portworxVolume: {}
      scaleIO: {}
      storageOS: {}
      quobyte: {}

emptyDir 临时存储 ​

  • Pod创建时新建空目录，Pod 删除数据清空。
  • 只能在同一 Pod 多容器共享数据。Pod 与 Pod 之间无法访问。
yaml
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    # 1. 定义卷
    volumes:
        - name: empty_volume # 卷名，挂载时引用
          emptyDir: # 类型空目录
              medium: '' #  挂载类型 ""(磁盘) / Memory
              sizeLimit: '2Gi' # 容量配额

hostPath 节点本地存储 ​

  • 数据存在Node上，Pod删除数据保留。
  • 生产环境 禁止使用
yaml
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    volumes:
        - name: path-volume # 卷名，挂载时引用
          hostPath:
              path: /app/logs # 宿主机路径
              type: DirectoryOrCreate # 不存在自动创建目录
              readOnly: true # 允许读写日志

PV && PVC 持久化存储 ​

yaml
# 申请 PV
apiVersion: v1
kind: PersistentVolume
metadata:
    name: base-pv
    labels:
        app: base-pv
spec:
    # 存储大小
    capacity:
        storage: 5Gi
    # 访问模式
    accessModes:
        - ReadWriteOnce # 单节点读写
    # 存储介质：使用宿主机本地目录
    hostPath:
        path: /data/base
        type: DirectoryOrCreate # 不存在就创建
    # 回收策略：删除PVC后PV保留数据
    persistentVolumeReclaimPolicy: Retain
---
# 申请 PVC
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
    name: base-pvc
    namespace: base
spec:
    # 访问模式
    accessModes:
        - ReadWriteOnce # 单节点读写
    resources:
        requests:
            storage: 5Gi # 申请5G存储空间
    # 关联pv
    selector:
        matchLabels:
            app: base-pv # pv的label

NFS网络存储 ​

  • 多节点共享存储，所有节点共用一份文件
bash
# 服务端安装
yum install nfs-utils
# 共享目录 /nfs/data
echo "/nfs/data *(rw,sync,no_root_squash)" >> /etc/exports
systemctl restart nfs-server
yaml
apiVersion: v1
kind: Pod
metadata:
    name: pod
spec:
    volumes:
        - name: pvc-volume # 卷名，挂载时引用
          nfs:
              server: 192.168.1.100 # 你的NFS服务IP地址
              path: /nfs/data # NFS服务端共享目录
              readOnly: false

持久化存储 ​

  • PV PersistentVolume：持久存储资源，管理员预先创建（NFS、云盘、存储阵列），独立于 Pod。
  • StorageClass：PV 的自动工厂，用来实现PVC 动态自动创建 PV，不用管理员手动一条条写 PV YAML。
  • PVC PersistentVolumeClaim：存储申请，开发声明需要多大存储、读写权限，K8s 自动绑定匹配 PV。
  • 流程：管理员创建 PV → 开发创建 PVC → PVC 绑定 PV → Pod 挂载 PVC 使用存储。

静态PV ​

  • 手动创建的 PV，需要管理员手动创建，不能自动创建 PV。
  • 持久存储资源，管理员预先创建（NFS、云盘、存储阵列），独立于 Pod。
  • PV 可以是本地存储、网络存储、云盘等。
yaml
# 申请 PV
apiVersion: v1
kind: PersistentVolume
metadata:
    name: test-pv
    namespace: default
    labels:
        app: test-pv
spec:
    # 存储大小
    capacity:
        storage: 5Gi
    # 访问模式
    accessModes:
        - ReadWriteOnce # 单节点读写
    # 存储介质：使用宿主机本地目录
    hostPath:
        path: /data/test
        type: DirectoryOrCreate # 不存在就创建
    # 回收策略：删除PVC后PV保留数据
    persistentVolumeReclaimPolicy: Retain

动态PV ​

  • 自动创建的 PV，根据 PVC 的需求，自动创建 PV。
  • 常用于云存储（腾讯云盘等）
yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
    name: cbs-sc-test
    # 如需设为集群默认存储类打开下面注释
    # annotations:
    #   storageclass.kubernetes.io/is-default-class: "true"
# CBS CSI固定驱动名称
provisioner: com.tencent.cloud.csi.cbs
# 拓扑感知：先调度Pod到节点 → 再在对应可用区创建CBS，必配
volumeBindingMode: WaitForFirstConsumer
# 测试：删除PVC自动销毁腾讯云CBS磁盘
# 生产：使用 Retain，会保留数据
reclaimPolicy: Delete
# 开启在线扩容（CBS支持磁盘扩容）
allowVolumeExpansion: true
parameters:
    # 磁盘类型
    # CLOUD_PREMIUM：高性能云盘(最小10Gi)
    # CLOUD_SSD：SSD云盘(最小20Gi)
    # CLOUD_HSSD：增强型SSD(最小20Gi)
    diskType: CLOUD_PREMIUM
    # 付费方式：POSTPAID_BY_HOUR按量付费（测试首选）；PREPAID包年包月
    diskChargeType: POSTPAID_BY_HOUR
    # 【可选固定可用区】多可用区集群建议删掉该行，自动跟随节点可用区创建磁盘
    # diskZone: ap-shanghai-2

PVC ​

  • 存储申请，开发声明需要多大存储、读写权限，K8s 自动绑定匹配 PV。
  • 程序引用的存储资源
yaml
# 申请 PVC
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
    name: test-pvc
    namespace: default
spec:
    # 访问模式
    accessModes:
        - ReadWriteOnce # 单节点读写
    resources:
        requests:
            storage: 5Gi # 申请5G存储空间
    # 关联pv
    selector:
        matchLabels:
            app: test-pv # pv的label

场景总结 ​

数据类型推荐方案
临时文件、容器间共享、缓存emptyDir（配置 sizeLimit）
普通配置文件ConfigMap
密码、密钥、凭证Secret
业务文件、上传附件PVC（文件存储 CSI）
数据库、时序数据PVC（块存储 CSI）
多 Pod 统一共享静态文件NAS/CephFS CSI
读取宿主机系统信息受控 hostPath + 固定节点调度

业务组件标准卷方案 ​

普通业务 Web / 微服务（SpringBoot、Node、Go） ​

  • 配置文件：ConfigMap
  • 账号密钥：Secret
  • 应用本地临时缓存：带 sizeLimit 的 emptyDir (Memory)
  • 业务上传文件 / 持久附件：PVC (CSI 文件存储)
  • 日志：不挂载卷写本地文件，容器日志输出 stdout，由宿主机日志收集器 (fluentd/loki) 采集

中间件（Redis、MQ、Elasticsearch） ​

  • Redis 持久化 RDB/AOF：PVC 块存储
  • Redis 堆内存临时文件：emptyDir（内存型）
  • ES 数据目录：高性能 PVC 块存储，严禁 hostPath
  • 配置文件：ConfigMap + Secret

数据库 MySQL / PostgreSQL ​

  • 必须使用云盘 CSI 或者 Ceph 块存储 PVC
  • 禁止：hostPath、普通 NFS 存储
  • 配套：定时快照备份、开启存储 QPS 限速防止 IO 打满节点

日志采集、监控组件（Prometheus、Grafana） ​

  • Prometheus 时序数据：高性能 PVC 块存储
  • 监控采集宿主机指标：有限使用 hostPath 挂载 /sys、/var/lib/docker

注意事项 ​

  • ❌禁止不带 sizeLimit 的 emptyDir 上线 → 容易 OOM / 磁盘占满节点宕机
  • ❌业务数据禁止 hostPath → 集群调度后数据丢失，无灾备
  • ❌数据库使用 NFS 存储 → 极易出现 IO 卡顿、数据损坏
  • ❌Secret 权限 0644 宽泛权限 → 存在密钥泄露风险
  • ✅ 所有持久数据统一走 CSI + StorageClass，统一管控存储生命周期
  • ✅ emptyDir 只存瞬时数据，重要数据一律落 PVC 并做备份
