一次性任务 ​

  • 运行一次性任务，保证任务正常执行完成，可配置失败重试、运行超时、多 Pod 并行执行。
  • 使用场景：项目初始化、测试。
yaml
apiVersion: batch/v1
kind: Job
metadata:
    name: once-job
    namespace: job

spec:
    # 任务最多重试2次
    backoffLimit: 2
    # 最长运行30s，卡死自动杀掉
    activeDeadlineSeconds: 30

    # 并行执行数（定时任务一般=1）
    parallelism: 1
    # 需完成的实例数
    completions: 1

    template:
        spec:
            restartPolicy: Never
            containers:
                - name: echo-task
                  image: busybox:1.35
                  command: ['echo', 'Job任务执行完成 Hello K8s Job']

周期性任务 ​

yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: backup-db-cron
  namespace: default
spec:
  # 1. 核心调度规则（必填）
  schedule: "0 2 * * *"

  # 时区配置（推荐配置，解决UTC时差问题）
  timeZone: "Asia/Shanghai"

  # 2. 并发策略（重点，生产必配）
  # Allow:允许并发；Forbid：禁止并发（上一个没跑完，本次跳过）；Replace：杀掉旧任务，运行新任务
  concurrencyPolicy: Forbid

  # 3. 任务错过执行的处理（比如集群停机导致某次定时没跑）
  # false：错过的任务直接丢弃；true：集群恢复后立刻补跑积压任务（极易瞬间大量并发）
  startingDeadlineSeconds: 1800 # 错过执行时间超过30分钟，就不再执行本次任务（推荐）

  # 4. 历史Job保留策略
  successfulJobsHistoryLimit: 3   # 成功的Job保留3个历史记录
  failedJobsHistoryLimit: 2      # 失败的Job保留2个历史记录
  # 不清理会堆积大量完成的Job资源，占用etcd存储

  # 5. Job模板：定时创建的Job配置
  jobTemplate:
    spec:
      # 重试次数：Pod执行失败重启Pod的次数
      backoffLimit: 2
      # 单次任务最大运行时长，超时强制杀死Pod（防止任务卡死）
      activeDeadlineSeconds: 3600

      # 并行执行数（定时任务一般=1）
      parallelism: 1
      # 需完成的实例数
      completions: 1

      template:
        spec:
          restartPolicy: OnFailure # 定时任务常用：失败重启，成功不重启；Never：从不重启
          containers:
          - name: backup
            image: mysql:8.0
            command: ["/bin/sh", "-c", "/scripts/mysql_backup.sh"]
            imagePullPolicy: IfNotPresent
            # 资源限制（生产强制添加，防止定时任务打满节点资源）
            resources:
              requests:
                cpu: 100m
                memory: 128Mi
              limits:
                cpu: 500m
                memory: 512Mi
            # 挂载脚本、备份存储
            volumeMounts:
            - name: script-volume
              mountPath: /scripts
            - name: backup-storage
              mountPath: /backup
            env:
            - name: MYSQL_PASSWORD
              valueFrom: secretKeyRef: {name: mysql-secret, key: password}
          volumes:
          - name: script-volume
            configMap: {name: backup-script-cm}
          - name: backup-storage
            persistentVolumeClaim: {claimName: backup-pvc}
