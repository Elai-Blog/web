Dockerfile ​

  • Dockerfile 是一个文本文件，包含一系列用于构建 Docker 镜像的指令。

  • 通过 Dockerfile，开发者可以将应用程序的构建过程标准化、自动化，确保在不同环境中构建出一致的镜像。

  • 官方文档：https://docs.docker.com/engine/reference/builder/#dockerfile-reference

指令说明 ​

FROM ​

  • FROM 基础镜像，当前新镜像是基于哪个镜像的，指定一个已经存在的镜像作为模板，第一条必须是FROM
  • 格式：FROM <镜像名>:<标签>
    • 常规镜像：FROM alpine:latest（轻量级 Linux 基础镜像）
    • 空镜像：FROM scratch（空镜像，用于构建自定义镜像）

LABEL ​

  • LABEL 为镜像添加元数据标签，用于描述镜像的相关信息。

USER ​

  • USER 指定该镜像以什么样的用户去执行，如果都不指定，默认是root. 一般不用指定
  • 格式：USER <用户名或UID>
  • 示例：USER appuser（切换到 appuser 用户执行后续指令）。

WORKDIR ​

  • WORKDIR 指定在创建容器后，终端默认登陆的进来工作目录，一个落脚点。
  • 格式：WORKDIR <工作目录路径>
  • 示例：WORKDIR /app（后续的 COPY、RUN 等指令会在 /app 目录下执行）。

RUN ​

  • 在构建镜像时执行命令（如安装依赖、编译代码等），每一行 RUN 会生成一个新层。
  • 格式：
    • shell: RUN 命令，示例：RUN yum -y install wget
    • exec: RUN ["可执行文件","执行参数1","执行参数2"]，示例 RUN ["yum","-y","install","wget"]

Copy ​

  • COPY 复制宿主机文件到容器
  • 格式：COPY <本地源路径> <镜像目标路径>
  • 示例：COPY ./app /app（将宿主机当前目录下的 app 目录复制到容器的 /app 目录下）。

ADD ​

  • ADD 复制宿主机文件到容器，与COPY类似，但是ADD还支持自动处理URL和解压tar压缩包。
  • 格式：ADD <本地源路径> <镜像目标路径>
  • 示例：ADD ./app.tar.gz /app（将宿主机当前目录下的 app.tar.gz 文件复制到容器的 /app 目录下并自动解压）。

ENV ​

  • 配置环境变量，在容器运行时可以使用。
  • 格式：ENV <键>=<值>
  • 示例：ENV MYSQL_ROOT_PASSWORD=123456（设置 MySQL 根用户密码为 123456）。

VOLUME ​

  • VOLUME 容器卷 宿主机与容器映射 用于数据保存和持久化。
  • 格式：VOLUME <路径>
  • 示例：VOLUME /data（声明容器将 /data 目录挂载为卷，用于数据持久化）。

EXPOSE ​

  • 声明容器运行时监听的端口，用于容器间通信和外部访问。
  • 格式：EXPOSE <端口号>
  • 示例：EXPOSE 80（声明容器监听 80 端口）。

CMD ​

  • 容器启动时的默认命令，可被 docker run 后的参数覆盖。
  • 一个容器最多只能有一个 CMD 指令。
  • 格式：
    • shell: CMD 命令，示例：CMD echo "hello world"
    • exec: CMD ["可执行文件","执行参数1","执行参数2"]，示例 CMD ["echo","hello world"]

Args ​

  • Args 定义构建时的参数，在构建镜像时可以通过 --build-arg 传递值。
  • 格式：ARG <参数名>[=<默认值>]
  • 示例：ARG APP_VERSION=1.0（定义一个参数 APP_VERSION，默认值为 1.0）。

构建镜像 ​

bash
# 格式
docker build -t [用户名]/[镜像名]:[版本号] .
# 打包默认Dockerfile文件  “.”必须有
docker build -t admin:v1 .
# 打包指定dockerfile “.”必须有
docker build -t admin:v2 -f Dockerfile-Admin .

参数说明 ​

参数说明
--tag, -t镜像的名字及标签，通常 name:tag 格式
-f指定要使用的Dockerfile路径
.上下文路径，指定 Dockerfile 所在目录。

文件名 ​

  • Dockerfile 默认文件名，docker build . 时会自动查找该文件。
  • Dockerfile-Admin 自定义文件名，docker build -f Dockerfile-Admin . 需要-f指定文件路径。

PHP环境构建 ​

  • 出现ERROR [internal] load metadata for docker.io错误时，说明镜像源被禁了，需要配置镜像源。
  • 配置参考：镜像源
dockerfile
# 设置镜像为 php:8.2-fpm
FROM php:8.2-fpm

# 设置维护者
LABEL maintainer="elai <elai.job@qq.com>"

# 编译安装核心扩展
# @see https://hub.docker.com/_/php?uuid=e869fb5e-0bec-49c8-bd69-dcf7ed0b45fe
RUN apt-get update && apt-get install -y \
    libfreetype-dev \
    libjpeg62-turbo-dev \
    libpng-dev \
    && docker-php-ext-configure gd --with-freetype --with-jpeg \
    && docker-php-ext-install -j$(nproc) gd

# 安装扩展
RUN pecl install redis \
    && pecl install swoole \
    && docker-php-ext-enable redis swoole GD

# 下载并安装 Composer（全局安装）
RUN curl -sS https://getcomposer.org/installer | php -- \
    --install-dir=/usr/local/bin \
    --filename=composer

GO打包构建 ​

dockerfile
# 第一步：打包
# 设置go1.25版本作为基础镜像 AS 命名为别名
FROM golang:1.25 AS builder
# 维护者信息
LABEL author=zouyl
# 设置工作区
WORKDIR /build
# 复制代码到容器
COPY ./ /build
# 设置代理
ENV GO111MODULE=on
ENV GOPROXY=https://goproxy.cn,direct
# 下载依赖
RUN go mod tidy

# 配置打包参数
# 禁用cgo
ENV CGO_ENABLED=0
# 设置服务器环境
ENV GOOS=linux
# 设置打包架构amd64/arm64
ENV GOARCH=amd64
# 进行打包
RUN go build -ldflags="-s -w" -o /build/app/backend/api/backend /build/app/backend/api/backend.go

# 第二步：运行镜像
# docker有一个基本镜像叫做scratch，它是一个空的镜像，在临时基础镜像上运行的应用程序只能访问内核
FROM scratch
# 设置镜像名
LABEL name=backend
# 配置镜像时区
ENV TZ=Asia/Shanghai
# 配置工作目录
WORKDIR /app
# 复制包到容器
COPY --from=builder /build/app/backend/api/backend /app/backend
# 复制配置文件到容器
COPY --from=builder /build/app/backend/api/etc /app/etc

EXPOSE 8100
# 运行服务
CMD ["./backend", "-f", "etc/backend-prod-api.yaml"]
